# Rules for working on AI OS (alpha)
- Follow AIOS_ALPHA_PLAN.md. One milestone at a time; stop and report after each.
- TypeScript strict. Validate all external input with zod. No `any` without a comment.
- No vendor AI SDKs; model access only through packages/core/src/model.ts. One approved exception (S4): the app builder runs the Claude Code CLI as a separate program (packages/core/src/apps/builder.ts).
- Model names/endpoints live in config only; never hardcode them elsewhere.
- Never read, write, or log real credentials. Secrets go through the keyring wrapper. Tests use the docker stack only.
- Tool risk tiers and approvals are enforced in code (approval broker), not just in prompts.
- All email-derived text passes through sanitize() and is wrapped in <untrusted> tags before reaching a model. Calendar event text (C1) and document text, cells, sheet names and file names (D1) are treated the same way: anyone can send an invite, and files come from anywhere.
- The triage worker has no tools. Add a test that fails if it is ever given one.
- Content from email may never write memory, call write-tier tools, or change config. Add tests.
- Every tool call is appended to the audit log.
- Verify provider API details (URLs, parameters, model names) against current docs; do not rely on memory.
- Explain any new dependency (why, license, maintenance status). Prefer small, reviewable commits.

## Commands
- `pnpm test` unit tests, `pnpm typecheck` strict type check.
- `pnpm test:stack:up` starts GreenMail and seeds the fixture mailbox; `pnpm test:stack:check` lists it over IMAP; `pnpm test:stack:down` stops it.
- `pnpm start` builds the UI and runs aios-core on 127.0.0.1:7777; `pnpm test:e2e` checks the chat end to end in Chromium with a mock model (mail checks need the test stack up). `scripts/test/mail.int.test.ts` runs against GreenMail and is skipped when it is down.
- `pnpm calendar:login` signs in to Google Calendar (C1). Tests never do: they use the pretend Google Calendar in `fixtures/calendar.ts`.
- Word and Excel files (D1 read, D2 edit) go through WordCraft's and GridCraft's CLIs. Tests never run the real apps: they use the pretend CLIs in `fixtures/documents.ts`. D2 edits only run from a hash-checked click and write a new file unless the user's own words ask to overwrite (then after a backup); change types map to app commands only in `packages/core/src/docs/recipes.ts`. The Edit button on a document card (D3) names only the card; `DocumentFiles.edit` resolves the card's file again and opens it in its app, never through the model. PDFs have no Edit button.
- Files (F1) are only those inside `[files] roots`, resolved in `packages/core/src/files/roots.ts`; changes run only from a hash-checked click (`files/actions.ts`) and never replace or delete a file. Tests use temporary folders, never the real home folder.
- The file summary worker (F2, `files/summarizer.ts`) has no tools, like triage, with a test; file descriptions are stored as plain text and shown only inside <untrusted> tags.
- Finding files by meaning (F3, `files/meaning.ts`): embeddings come only from `[models.embeddings]`, Ollama on loopback, through `ModelClient.embed`; what is embedded is sanitized and wrapped in <untrusted source="document">. The results card's "why it matched" is written by code, and its snippets are file text shown as plain text only; each Open resolves the file again inside `[files] roots` (`files/results.ts`). Tests use a pretend embedder (`scripts/test/file-meaning.test.ts`).
- Screens (S7, replacing S6's places): the chat is always full screen on its own workspace (its screen is `[screen] monitor`); apps open on another screen or the next workspace, and windows that land on the chat's workspace are moved off it, only through `packages/core/src/apps/window.ts`. Monitor names and workspace numbers are checked before they reach a Hyprland dispatch; no workspace is pinned to a screen (Omarchy 4 owns that). Window titles are never read or shown (pages set them). The top bar's AI button reads one flag character (`apps/bar.ts`). Tests use the pretend Hyprland in `packages/core/test/apps.test.ts`, never a real session.
- Built apps (S5) reach aios-core only at `/app-link/` with their own token (`apps/link.ts`); a request from an app only posts a Change card, never builds, and its words never reach the chat model. The policy and Change button are re-applied after every build and at start (`AppBuilder.seal`).
- The local model (L1, `[models.local]`) is Ollama on loopback only. The system assistant's worker (`assistant/worker.ts`) has no tools, like triage, with a test; file names, window titles and process names reach it inside <untrusted source="system"> tags. Move to Trash and Close run only from a hash-checked click (`assistant/review.ts`); the Trash never overwrites. Tests use fake /proc readers, a pretend Hyprland and temporary folders.
- Sending files by email (M1): only files in `[files] roots`, through `mail/outgoing-files.ts`; their bytes are in the draft's hash and read again on the Send click, which stays the only way mail goes out. Tests use temporary folders.
- Packaging (P1): `install.sh` installs a release tag into `~/.local/share/aios/app`; `pnpm doctor` and `/doctor` are written by code only and never show a secret; `pnpm backup` never includes keyring secrets, and `--restore` refuses links, `..` and anything outside AI OS's folders. Tests use temporary homes and pretend commands (`scripts/test/install.test.ts`).
- Astra (R1): the app's names come only from `packages/shared/src/brand.ts` (`appIds`): a new install is Astra (`~/.config/astra`, `astra.service`, keyring `astra`, port 7780); one with only `~/.config/aios/config.toml` keeps the AI OS names. Never rename built apps' `aios-app-*` ids, the change-button or CSP markers, the bar id or the window class. The `astra` command (`scripts/src/astra.ts`) passes on only the flags each script takes. The Arch package (`packaging/arch`) writes nothing in a home folder; `astra setup` does, after asking.
- To-dos (T1) live in `~/.config/aios/todos.md` (`todos/list.ts`). `todo_add`, `todo_update` and `todo_done` are device tier with no confirm card, so outside text can never add, move or tick off one (test: `scripts/test/hostile-todos.test.ts`); only a card's Remove click deletes. Reminders fire from code (`todos/reminders.ts`), held in quiet hours and pause.
- The morning brief (T2, `brief/brief.ts`) is gathered by code; its intro comes from the local model with no tools (a test checks), inputs inside <untrusted>, or from code without it. Read only.
- Videos (V1, `video/tools.ts`): `video_play` is device tier, so outside text only gets a confirm card. mpv gets code's options, then `--`, then one file from `[files] roots` that is a video by its bytes or one https link checked by `checkVideoLink` (`video/play.ts`). `/play` picks the video in code (`pickVideo`) and runs `video_play` through the registry, never the model. Tests use a pretend mpv and temporary folders.
- Widgets (W1, `widgets/widgets.ts`): tiles at the bottom of the chat screen are written by code (counts, times and the user's own to-dos; never mail, invite or document text). Only `/pin`, `/unpin` and a tile's own buttons change what is pinned, through `Shell.handle`; there is no tool for it (test: `packages/core/test/widgets.test.ts`).
- The knowledge base (K1, K2: `knowledge/crawler.ts`) writes only `~/.config/aios/knowledge/about-me.md`. Each email, document, chat stretch or calendar day is read once (`knowledge/ledger.ts`) by a structured call with no tools, like triage, with a test; the item, headers included, is sanitized inside one <untrusted> wrapper (`knowledge/extract.ts`), and code merges the notes. It is never memory: `knowledge_read` returns it as outside text like an email (test: `scripts/test/hostile-knowledge.test.ts`). Tests use a pretend mailbox and temporary folders.
- Voice (V2, `speech/dictation.ts`): speech becomes text only through `ModelClient.transcribe`, from `[models.speech]`, a whisper.cpp server on loopback. The chat posts 16 kHz mono WAV to `/speech` (same origin only, size capped by `maxSeconds`); the words go back to the message box only, never sent, posted or given to the chat model by core (test: `packages/core/test/speech.test.ts`). Audio is never stored; the audit log gets length and outcome only. Tests use a pretend whisper server and Chromium's fake microphone.
- Test mailbox: `john@aios.test` / `test-only-password` on IMAP 127.0.0.1:3143, SMTP 127.0.0.1:3025 (plain, local only).
